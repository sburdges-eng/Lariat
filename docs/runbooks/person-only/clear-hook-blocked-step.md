# Clear a hook-blocked step (commit gate, branch lock, file claim, schema-version bump, post-edit typecheck)

**Why this is yours:** When a hook blocks an agent it must stop and hand you the step (`CLAUDE.md:303-304`; `AGENTS.md:83,85`); agents may never `--no-verify` or skip a hook (`.claude/agents/implementer.md:55`, `.claude/agents/swift-port.md:72`). Every escape hatch is an env var or a file only you set: `LARIAT_ALLOW_ANY_BRANCH=1` (`scripts/check-session-branch.mjs:44,54`), `LARIAT_ALLOW_SCHEMA_NO_BUMP=1` (`scripts/check-schema-version-bump.mjs:24,69-73`), removing the `SESSION_BRANCH` lock (`scripts/check-session-branch.mjs:76`, `scripts/worktree.sh:225-233`), retiring another agent's file claim, or `SKIP_SIMPLE_GIT_HOOKS=1` (`.git/hooks/pre-commit:3-6`).
**Unblocks:** The one commit or `.ts` edit the agent stopped at, and everything queued behind it on that branch (its PR).

## Steps
1. **Find the pending instance.** Chat first (the agent's "hook blocked — handing to Sean" message); else the `grep` above; else `/person-only` with no argument builds the queue (`AGENTS.md:87`) → expect one refusal line, a branch, and a worktree path. If not: nothing is pending — stop.
2. **Reproduce it yourself, read-only.** `cd <worktree> && git branch --show-current && cat "$(git rev-parse --git-dir)/SESSION_BRANCH" 2>/dev/null; node scripts/check-session-branch.mjs; echo branch=$?; node scripts/check-schema-version-bump.mjs; echo schema=$?` → expect the same `✗` line and a non-zero code (both scripts only read git and `.agent-sessions/`: `check-session-branch.mjs:19-21,89`, `check-schema-version-bump.mjs:31-33,38,51`). If both print 0, the block is lint/tsc (gate A, B5 or C): `npm run lint >/dev/null 2>&1; echo lint=$?; npm run typecheck >/dev/null 2>&1; echo tsc=$?` → expect one non-zero. If nothing reproduces: the agent's state moved — tell it to retry the commit.
3. **Decide by gate.** Pick the row that matches the refusal; only the *override* column is yours, the *fix* column can go straight back to the agent.
   - **B1 branch name** (`check-session-branch.mjs:51-55`). Fix: rename — `git branch -m <bad> feat/<short-name>` (or `fix/` `chore/` `wip/`), then `echo feat/<short-name> > "$(git rev-parse --git-dir)/SESSION_BRANCH"` because the lock still names the old branch (`scripts/worktree.sh:125`). Override, only for a legacy branch (`cursor/…`, `bundle-h-*`) that already has an open PR you want to keep: `LARIAT_ALLOW_ANY_BRANCH=1 git commit …` yourself in that worktree (`:54`, `scripts/worktree.sh:60`).
   - **B2 branch lock** (`check-session-branch.mjs:72-77`). Another session moved HEAD. Fix, when the lock is right: `git switch <expected>` (the guard's own advice, `:75`). Override, when the branch change was intended: `scripts/worktree.sh unlock && scripts/worktree.sh lock <current-branch>` (`scripts/worktree.sh:209-233`). Detached HEAD (`:68`): `git switch <branch>` first.
   - **B3 file claim** (`check-session-branch.mjs:115-123`). `node scripts/agent-session.mjs list` → who claimed it and when. Same person under another tool name (the guard assumes `gemini` when `AGENT_NAME` is unset, `:88`) → `AGENT_NAME=<tool> git commit …` (`.claude/skills/person-only/SKILL.md:116`). Other agent genuinely live (updated < 30 min, `:83,101`) → tell the blocked agent to wait for the claim to expire or split the file. Other agent dead → retire its claim: edit `.agent-sessions/<tool>.json`, move the paths to `claimedFilesRetired` and add a dated `note` (precedent: `.agent-sessions/cursor.json`). The guard reads the `.agent-sessions/` of the checkout being committed in (`:84-85`); a linked worktree has its own board (`scripts/worktree.sh:173-177`).
   - **B4 schema bump** (`check-schema-version-bump.mjs:76-79`). Real DDL → hand back: bump `export const SCHEMA_VERSION` at `lib/db/schema/core.ts:33` (6 today) in the same commit — not person-only. Comment-only or heuristic miscatch (the regex at `:60-61` matches DDL words inside comments) → override yourself: `LARIAT_ALLOW_SCHEMA_NO_BUMP=1 git commit …` (`:24,69-73`) and say why in the commit body.
   - **A / B5 lint or typecheck** (`scripts/cursor-precommit-gate.sh:42-45`; `package.json:297`). No override exists in either gate, by design. Error is in the agent's own diff → hand back "fix it" (`.claude/agents/implementer.md:55`). Error pre-exists on `origin/main` (`git fetch origin && git diff origin/main --stat -- <file>` shows no change from the agent) → the fix is its own `fix/` PR first, then the agent rebases (`CLAUDE.md:169-170`; `docs/superpowers/plans/2026-07-02-lariat-native-a4-2-costing-detail.md:2832`). Warnings never block (`docs/lint-baseline.md:7-9`). Last resort, yours only, only when `main` itself is broken and a service-day fix cannot wait: commit from your own Terminal (gate A does not run there) with `SKIP_SIMPLE_GIT_HOOKS=1 git commit …` (`.git/hooks/pre-commit:3-6`; `docs/lint-baseline.md:26-27` names `--no-verify` as the same emergency valve) — write the reason in the commit body and open the fix PR the same day.
   - **C post-edit typecheck** (`.claude/settings.json:55`). It runs whole-repo `tsc`, so one pre-existing tsc error anywhere blocks every `.ts` edit for the session. Error is in the agent's edit → hand back. Pre-existing → the tsc fix PR goes first, or tell the agent to keep to non-`.ts` files until it lands. Not present on `origin/main` until #674 merges.
4. **Act.** Run the chosen override in the agent's worktree yourself, or hand the agent-fixable fix back → expect `git -C <worktree> log -1 --format='%h %D %s'` to show the new commit on the intended branch. If not: re-run step 2 — the refusal text tells you which gate is still unhappy.
5. **Tell the waiting agent, in the same chat.** `Hook cleared: <refusal line> — <what you did / override used>. Continue from <its step>.` → expect the agent to resume without re-asking. If its session is gone, append the same line with today's date to `.agent-sessions/handoff.md` (`AGENTS.md:85`).
6. **Name any override in the PR.** If you used `LARIAT_ALLOW_*`, `SKIP_SIMPLE_GIT_HOOKS`, an unlock or a claim retirement, make sure the commit body or PR description says so → expect the reviewer to see it without reading this runbook. If not: `gh pr edit <n> --body-file -` with the line added.

## Pass / fail
Pass = all of: the blocked commit or edit landed on a `feat/|fix/|chore/|wip/` branch; `node scripts/check-session-branch.mjs && node scripts/check-schema-version-bump.mjs` now exits 0 in that worktree; every guard is still installed (`.git/hooks/pre-commit:12` unchanged, `git config --get core.hooksPath` empty, `SESSION_BRANCH` present unless you unlocked on purpose); and any override is written down (step 6). Fail = `--no-verify` or `SKIP_SIMPLE_GIT_HOOKS` used without a written reason, a guard script edited to pass, or the agent resumed on a branch other than the one it was locked to. For a recurring instance, "handled" = the agent received a step-5 line it can act on.

## If something goes wrong
- **Override "did nothing":** the env var must be on the same line as `git commit` (`LARIAT_ALLOW_ANY_BRANCH=1 git commit …`); `env | grep LARIAT_ALLOW` shows whether it leaked into the shell instead.
- **Commit landed on the wrong branch:** do not `reset --hard` (`.claude/skills/person-only/SKILL.md:117`). `git switch <right-branch> && git cherry-pick <sha>`, then tell the agent to drop the stray commit from its branch.
- **Removed `SESSION_BRANCH` by mistake:** `scripts/worktree.sh lock <branch>` while on that branch (`scripts/worktree.sh:209-223`).
- **Retired a claim that was live:** put the paths back into `claimedFiles` in `.agent-sessions/<tool>.json` (the `claimedFilesRetired` list still has them) and tell that agent in chat.
- **`.git/hooks/pre-commit` missing:** `npx simple-git-hooks` from the repo root reinstalls it from `package.json:296-298` (the `prepare` script at `:43` does the same on `npm install`).
- **Gate A never fires in Claude Code:** the hook path is stale (`~/Dev/…`, unmounted SSD) — that is `origin/main`'s `.claude/settings.json:44`; the working-tree copy in PR #674 points at `/Users/seanburdges/lariat_dev/Lariat/`. Until it merges, B1–B5 still run from `.git/hooks/pre-commit`.
- **Who to tell:** the agent that handed it over, in its chat. Nobody else — owner-only.
