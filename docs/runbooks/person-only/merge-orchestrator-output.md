## Steps
1. **Open the row and its task.** `grep -n '^|' ORCHESTRATOR_STATUS.md` and `grep -n -A22 'id: <id>' tasks.yaml` → status row plus the task's `description`, `acceptance_tests`, `paths_touched` (`tasks.yaml:7`; schema `coordinator.md:13-25`). The reviewer's findings and test counts are in the row's Notes (`reviewer.md:41-53`).
2. **Decide any `review_red` / `red` row first.** They wait on you (`coordinator.md:40,44,63`). (a) Retry — no `/orchestrate retry` exists; tell the coordinator session in chat "retry <id> with the findings in Notes" so it re-dispatches the implementer. (b) Drop — set Status `dropped — <why>`. (c) Fix it yourself in the worktree, then continue at step 3. Never remove a red worktree before you have read its error (`coordinator.md:62`).
3. **Read the diff yourself.** `git -C .claude-worktrees/<id> log --oneline origin/main..HEAD` → one commit `<id>: ...` (`implementer.md:36`). `git -C .claude-worktrees/<id> diff origin/main...HEAD --stat` → only files in `paths_touched` (`reviewer.md:38`); then read the whole diff. Out-of-scope files, a deleted or weakened test (`implementer.md:56`), or a HACCP/PIN/audit change you did not expect → do not merge; go to "If something goes wrong".
4. **Rename the branch if it is `orch/<id>`.** *(skip if pre-done)* The coordinator names branches `orch/<id>` (`coordinator.md:34`), but the pre-commit guard refuses commits on any prefix other than `feat/ fix/ chore/ wip/` (`scripts/check-session-branch.mjs:31,44-56`, wired at `package.json:297`), so the implementer either used `LARIAT_ALLOW_ANY_BRANCH=1` or already picked a legal name. `git -C .claude-worktrees/<id> branch -m feat/orch-<id>` → `git -C .claude-worktrees/<id> branch --show-current` prints `feat/orch-<id>`.
5. **Rebase onto `origin/main`.** *(skip if pre-done)* You may; the subagents may not (`implementer.md:53`). `git -C .claude-worktrees/<id> rebase origin/main` → `Successfully rebased`. Conflict → `git -C .claude-worktrees/<id> rebase --abort`, hand the rebase to an agent session, and do not merge a branch gated against a stale `main` (CLAUDE.md:169).
6. **Run the acceptance tests and the verify gate in the worktree.** *(skip if pre-done — but read the pasted `exit=` line)* The coordinator's raw `git worktree add` gives no deps; if `.claude-worktrees/<id>/node_modules` is missing: `ln -s "$PWD/node_modules" .claude-worktrees/<id>/node_modules; ln -s "$PWD/.venv" .claude-worktrees/<id>/.venv` (what `scripts/worktree.sh:130-140` does for its own worktrees). Then `cd .claude-worktrees/<id>`, run each `acceptance_tests` command, then `npm run version:stamp && npm run verify > /tmp/verify.log 2>&1; echo "exit=$?"` → `exit=0` (`version:stamp` first — `verify` is not hermetic, CLAUDE.md:179-184; read the exit code, never stdout, `:201-204`). Any `swift test` line (`tasks.yaml:56-57,83-84`) cannot run on this machine — CLT-only, no XCTest (CLAUDE.md:185-187); `swift build` from `LariatNative/` is the local signal and `native-ci` on the PR is the gate. If the diff touches a protected surface, also run its §15 suite (`docs/PROTECTED_CONTRACTS.md:481`; a broad pass does not replace it, `:533`). Red → do not merge. `cd` back to the repo root.
7. **Push the branch and open the PR.** *(skip if pre-done)* `git -C .claude-worktrees/<id> push -u origin feat/orch-<id>` then `(cd .claude-worktrees/<id> && gh pr create --fill)` → a PR URL. CI runs only on `pull_request` and on pushes to `main` (`.github/workflows/ci.yml:21-23`) — a pushed branch with no PR has no gate.
8. **Wait for CI.** `gh pr checks <N> --watch` → `typecheck · tests · build` pass (`ci.yml:49`); `native-ci` pass when it ran — it fires only for `LariatNative/**`, `tests/fixtures/**`, `lib/db.ts`, the BEO/BOM oracle scripts (`.github/workflows/native-ci.yml:21-40`); `smoke` (`desktop-smoke.yml:23`) only for `desktop/**`, `package.json`, `lib/db.ts` and friends (`:13-20`). `Cursor Bugbot` reporting `skipping` is not a gate. Red → "If something goes wrong".
9. **Merge.** `gh pr merge <N> --merge` → `Merged pull request #<N>` (merge commits allowed: `gh repo view --json mergeCommitAllowed` = `true`; a merge commit keeps the task revertible with `-m 1`). Record the SHA: `gh pr view <N> --json mergeCommit -q .mergeCommit.oid`. Never `git push origin main` (CLAUDE.md:147) — nothing on GitHub stops you: `main` has no branch protection and no rulesets (`gh api repos/sburdges-eng/Lariat/branches/main/protection` → 404; `.../rules/branches/main` → `[]`).
10. **Remove the worktree and branch — yours, not an agent's** (`coordinator.md:62`; `.claude/skills/person-only/SKILL.md:36`). Only after the SHA is recorded: `git worktree remove .claude-worktrees/<id> && git branch -d feat/orch-<id>` → gone from `git worktree list` and `git branch`.
11. **Update the row** — see "Record the result". Repeat from step 1 for the next row; dependents that were waiting on this task are now eligible for the coordinator (`coordinator.md:31`).

## Pass / fail
One row is handled when: the PR is merged into `origin/main` with every check green; the verify gate exited 0 on the rebased branch; the diff stayed inside `paths_touched` with no weakened or deleted test (`reviewer.md:22-23,38`; `implementer.md:56`); the worktree and branch are removed; and the `ORCHESTRATOR_STATUS.md` row reads `merged` with PR number + SHA. Do not merge on: any red acceptance test or `exit≠0`, out-of-scope files, a rebase conflict you did not resolve, red CI. A `review_red`/`red` row is handled when your decision (retry / drop / fixed) is written in the row — not when it is hidden.

## If something goes wrong
- Verify or acceptance red on the rebased branch → do not merge. Set the row to `red` (or `review_red` if the reviewer missed it) with the command and the first 30 lines of the error in Notes (`coordinator.md:70`); leave the worktree in place (`coordinator.md:62`); ask the coordinator session in chat to re-dispatch the implementer with that context.
- Rebase conflict → `git -C .claude-worktrees/<id> rebase --abort`; hand it to an agent session (not the implementer subagent — `implementer.md:53`) to rebase, re-run the gates, and push; you still merge.
- Wrong thing merged → `git revert -m 1 <merge-sha>` on a `fix/` branch → PR → merge. Then set the row back to `review_red` with the reason.
- Row says `ready_to_merge` but the worktree is gone → `git branch --list 'orch/*' 'feat/orch-*'`; if the branch is also gone the work is lost — set the row to `red — worktree missing` and re-queue the task in `tasks.yaml`.
- Never `--no-verify`, never `reset --hard`, never edit a failing test to pass (`implementer.md:54-56`; `SKILL.md:127`).
- Tell: append the blocker to `.agent-sessions/handoff.md` and the row's Notes in `ORCHESTRATOR_STATUS.md` (AGENTS.md:85).
