## Pass / fail
- **One batch is handled** when: every path in it was on the manifest as duplicate-of-canonical or stale-copy with proof (never `unknown`); your `confirm batch N` line exists before anything moved; after the move the app launched with real rows and clean stderr, `VERIFY_EXIT=0` and `swift build` exit 0, `integrity_check` = `ok` with counts intact (`phase-d-e-checklists.md:48-49`); the batch section is filled. - **E5 is done** when every manifest row reads deleted / kept / relocated — PII rows relocated + verified, never deleted (`phase-e-consolidation.md:26`; `phase-d-e-checklists.md:59`) — and the quarantine has been emptied after the E6 archive.

- **Any red in 7–9, or any doubt:** put the batch back — `for d in ~/lariat-delete-quarantine/batch-N/*; do mv "$d" "<original parent dir>/"; done` using the original paths from the batch section; re-run 7–9; write "restored YYYY-MM-DD" in the section. E5 stops until an agent explains the red in chat.
- **Quarantine already emptied:** restore from the E4 backup — restore-tested by definition (`phase-d-e-checklists.md:46-47`); the E4 evidence names the command.
- **`integrity_check` not `ok` on the live DB:** unrelated to a move — stop, do not repair, hand the output to an agent in chat (same rule as `c4-backup-restore-drill.md:46`).
- **Gate red in step 8:** never `npm rebuild better-sqlite3` (`CLAUDE.md:99-100`); a `no such module 'XCTest'` is this machine, not the code (`CLAUDE.md:116-121`). Restore the batch anyway until the red is explained.
- **SSD unmounts mid-batch** (`test -d ~/Dev` → `exit=1`): finish only local rows; SSD rows stay pending.
- **A path on disk not on the manifest, or doc and disk disagree:** the disk wins — never delete it; hand it to E3 as `unknown` (`phase-d-e-checklists.md:45`).
- **Anything PII** (`lariat-data-sources`, the pre-scrub copies, `lariat-ops-lariathr-bundles.zip` in the salvage archive — `app-lineage-salvage.md:26-29`): relocate + verify, never delete (`phase-e-consolidation.md:26`; `phase-d-e-checklists.md:59`).
