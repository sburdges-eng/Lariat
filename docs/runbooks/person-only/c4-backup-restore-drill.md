## Steps
All steps on the venue Mac, same Terminal window, from the repo root.

1. **Set the three paths.** `export LIVE="$HOME/Library/Application Support/Lariat/data"; export LARIAT_BACKUP_DIR="$HOME/lariat-backups"; export DRILL="$HOME/lariat-restore-drill/data"; ls -la "$LIVE/lariat.db"` → expect: the live DB listed. If not: stop — find the real DB first (resolution order: `LARIAT_DATA_DIR` → repo `data/` → App Support, `LariatNative/Sources/LariatModel/StationCatalog.swift:143-173`).
2. **Confirm the audit trail dir.** `ls "$LIVE/audit"` → expect: `management-actions.jsonl`. If "No such file" (the measured state): no management action has been logged by this install yet (native + web both write `<dataDir>/audit/management-actions.jsonl`, `lib/auditLog.mjs:35`, `LariatNative/Sources/LariatDB/DataDirectory.swift:14-23`). Do **not** substitute the repo's `data/audit` — different data root. Run `mkdir -p "$LIVE/audit"` and write "audit dir empty at drill time" in the log.
3. **Take the backup — the live app may keep running** (sqlite online backup API, `phase-c-backup.sh:6-9,159`). `scripts/phase-c-backup.sh backup --db "$LIVE/lariat.db" --audit-dir "$LIVE/audit" > /tmp/c4-backup.txt 2>&1; echo "exit=$?"; cat /tmp/c4-backup.txt` → expect: `exit=0`, manifest printed, last lines `phase-c-backup: wrote $HOME/lariat-backups/<UTC stamp>` + a verify hint (`phase-c-backup.sh:165-177`). If `exit=2`: usage/env error — read the `phase-c-backup:` line (`:34,38`).
4. **Pin the backup dir.** `export BDIR="$(ls -d "$LARIAT_BACKUP_DIR"/*Z | tail -1)"; ls -l "$BDIR"; cat "$BDIR/SHA256SUMS"` → expect: `lariat.db`, `audit.tar.gz`, `SHA256SUMS`, `manifest.txt` (`phase-c-backup.sh:159-174`; pinned by `tests/js/test-phase-c-reconcile.mjs:530-532`). If not: rerun step 3.
5. **Run the scripted restore drill.** `scripts/phase-c-backup.sh verify "$BDIR" > /tmp/c4-verify.txt 2>&1; echo "exit=$?"; cat /tmp/c4-verify.txt` → expect: every line `[PASS]` (checksums, `integrity_check: ok`, `foreign_key_check: clean`, three row counts > 0, `audit.tar.gz: readable`), final `phase-c-backup verify: PASS`, `exit=0` (`phase-c-backup.sh:69-134`). If `FAIL`: see "If something goes wrong".
6. **Restore into the scratch DB** (c4:20 "restore into scratch DB"). `mkdir -p "$DRILL" && cp "$BDIR/lariat.db" "$DRILL/lariat.db" && tar -xzf "$BDIR/audit.tar.gz" -C "$DRILL" && ls -la "$DRILL" "$DRILL/audit"` → expect: `$DRILL/lariat.db` and `$DRILL/audit/` (tarball was built with `-C parent basename`, `phase-c-backup.sh:161`). If not: check free disk, rerun.
7. **Record the checksum match** (c4:20 "checksum match recorded"). `grep lariat.db "$BDIR/SHA256SUMS"; shasum -a 256 "$DRILL/lariat.db"; sqlite3 "$DRILL/lariat.db" 'PRAGMA integrity_check;'` → expect: the two SHA-256 strings identical; `ok`. Copy all three lines verbatim into the log. If the hashes differ: torn copy — redo step 6; if still different, stop (disk problem).
8. **Open the restored DB in the native app** (c4:20 "app opens"). Leave the live app alone. `LARIAT_DATA_DIR="$DRILL" LariatNative/build/Lariat.app/Contents/MacOS/LariatApp &` (launch pattern: `LariatNative/Scripts/PACKAGING.md:53-56`) → expect: a Lariat window with real rows on a data board (86 / Shows / BEO), no degrade tile, and **no** stderr line `lariat.db not found at …` (`LariatNative/Sources/LariatDB/LariatWriteDatabase.swift:10`) or `first run — created a fresh database` (`LariatNative/Sources/LariatApp/UI/Shell/LariatApp.swift:125`). If either line prints: the env var did not take — ⌘Q at once and retry step 8; the live DB is untouched (bootstrap only seeds where no DB exists, `FirstRunBootstrap.swift:9-16`).
9. **Prove the window is on the scratch copy, then quit it.** `lsof -c LariatApp 2>/dev/null | grep -c lariat-restore-drill` → expect: `1` or more. Then ⌘Q the drill window. If `0`: the window is on another DB — ⌘Q, redo step 8.
10. **Optional (closes c4:18 too): reconcile runs clean on the backup copy.** `npx -y node@24 scripts/phase-c-reconcile.mjs --db "$DRILL/lariat.db" --audit-dir "$DRILL/audit"; echo "exit=$?"` (flags: `scripts/phase-c-reconcile.mjs:11-16`; read-only on the DB, writes only a snapshot under `data/cache/`, `:19-22`) → expect: PASS table, `exit=0`. If not: note the failing invariant in the log; it does not fail this drill.
11. **Gather the evidence text.** `cat "$BDIR/manifest.txt" /tmp/c4-verify.txt` → expect: manifest + verify output on screen. Paste both verbatim into the log file in "Record the result" (`~/lariat-backups` and `backups/` are outside git — `.gitignore:36`).

## If something goes wrong
- **Nothing to roll back.** The drill never writes to the live DB or audit dir (`.backup` snapshot, `phase-c-backup.sh:6-9`; verify restores to a temp dir, `:76-80`; the app opens only `$DRILL`). Keep `$BDIR` — it is the C5 rollback precondition (`c5:29`). Only `~/lariat-restore-drill` is disposable.
- **`integrity_check` FAIL in step 5:** rerun step 3. If `sqlite3 "$LIVE/lariat.db" 'PRAGMA integrity_check;'` is not `ok` on the live DB itself, that is a C4 Integrity alarm (`c4:31`) — stop, keep `/tmp/c4-verify.txt` and `$BDIR`, hand to an agent in chat. Do not "repair" the live DB.
- **`row count <table> (want > 0)` FAIL:** the spot-check resolves roster as the first of `staff` / `entities_employees` / `sevenshifts_users` then `locations`, `audit_events` (`phase-c-backup.sh:96-116`). If the venue schema renamed one, rerun step 5 with `LARIAT_VERIFY_TABLES="entities_employees locations audit_events"` (`:28-30,108`) and say so in the log. If a table is genuinely empty, the live DB is missing seed data — log it; not a drill fix.
- **`die: audit dir not found`** (`phase-c-backup.sh:151`): step 2 was skipped.
- **App shows the degrade tile / `lariat.db not found at <path>`:** `LARIAT_DATA_DIR` typo — the app never creates a DB outside App Support (`FirstRunBootstrap.swift:9-16`). ⌘Q, fix, retry step 8.
- **Never** `cp` the live `lariat.db` or its `-wal`/`-shm` while the app runs (`phase-c-backup.sh:7-9`); never include `$LIVE/keys/` in any backup (`docs/OPERATIONS.md:106`) — the script does not, keep it that way.
- Any surprise touching HACCP or `docs/PROTECTED_CONTRACTS.md` surfaces: stop and report in chat; do not improvise.
