**Why this is yours:** The weekly Toast Web export is the source of truth for `toast_sales_*` / `toast_labor_*` — a person downloads it and drops it into `data/imports/toast-weekly/` (`scripts/toast-weekly-ingest.mjs:4-11`). Only you have Toast Web access; no Toast credentials exist in the agent environment (`docs/runbooks/toast-category-sales-12mo.md:14-15`; `.env.local` has no `TOAST_*` vars, measured 2026-09-02), so the API-pull path (`scripts/toast-weekly-pull.mjs`) is unconfigured. The optional launchd install is per-user `launchctl` on your Mac (`scripts/toast_weekly/com.lariat.toast-weekly.plist.template:13-19`).
**Unblocks:** `toast_sales_daily` / `toast_sales_dow` / `toast_sales_hour` refresh (`scripts/ingest-toast-timeseries.mjs:50-52`), `toast_sales_summary` (`scripts/ingest_toast_sales_summary.py:2`), and the never-yet-created `toast_labor_summary` / `toast_labor_by_job` (`scripts/ingest_toast_labor.py:16-19`). Live DB today: `toast_sales_daily` stops at `shift_date` 2026-04-17, imported 2026-04-19; no `toast_labor_*` tables exist.
**Where:** Toast console (browser) for the export; this laptop — the serving Mac (`go-live-venue-data.md:10`) — for the drop and ingest.  **Time:** 10 min weekly; ~30 min the first time (agent fixes below must land before zips can be ingested).

## Steps
1. **Decide whether a drop is due.** `sqlite3 -readonly "$HOME/Library/Application Support/Lariat/data/lariat.db" "SELECT MAX(shift_date), COUNT(*), MAX(imported_at) FROM toast_sales_daily;"` → expect: `MAX(shift_date)` is last Sunday or later. If it is older (today: `2026-04-17|4407|2026-04-19 00:14:18`): a drop is due — continue. Also `ls data/imports/toast-weekly/` → files already there means a prior drop never ingested; go to step 4. Trigger cadence is Mondays (template `:9`, `Weekday 1 / 06:05`); an agent may also ask in chat.
2. **Export from Toast Web.** In the Toast console, export the three sales timeseries reports as CSV (the repo records the file shape, not the Toast menu path). The router keys on the filename (`scripts/toast_weekly/router.mjs:11-19`) and the parser on the exact header (`scripts/lib/toast_csv.mjs:172-174`):
   - `sales-by-date-<anything>.csv` — header `Date,Net Sales,Orders,Guests,Group,Date Range`, dates `MM/DD/YYYY` (`toast_csv.mjs:20-21`)
   - `sales-by-day-<anything>.csv` — header `Day,Net Sales,Orders,Guests,Group,Date Range`
   - `sales-by-time-<anything>.csv` — header `Time,Net Sales,Orders,Guests,Group,Date Range`
   All three are required in one drop or the timeseries step exits 1 (`ingest-toast-timeseries.mjs:56-61`). `Group` must be `1` or `2` (`toast_csv.mjs:164`). **Export the full history, not just last week:** the ingest deletes every row for the location and re-inserts what you exported (`ingest-toast-timeseries.mjs:127`). Today's rows span 2019-04-06 → 2026-04-17 as a prior-year comparison ("Apr 6, 2020 - Apr 17, 2026" vs "Apr 6, 2019 - Apr 17, 2025"), so set the range to 2020-04-06 → last complete day with the prior-year comparison on, or history shrinks to your window.
   - Optional once the agent fix is in: `SalesSummary_<YYYY-MM-DD>_<YYYY-MM-DD>.zip` (`router.mjs:23`) and `LaborBreakDown_<YYYY-MM-DD>_<YYYY-MM-DD>.zip` (`router.mjs:24`; must contain `Labor cost summary.csv` + `Labor cost by job.csv`, `ingest_toast_labor.py:294-302`). Keep Toast's own names — the period is parsed from the filename (`ingest_toast_labor.py:128-131`).
3. **Drop the files.** Move them into `data/imports/toast-weekly/` (top level; dotfiles and subfolders are ignored, `toast-weekly-ingest.mjs:74-80`). `ls -la data/imports/toast-weekly/` → expect: your files, nothing else except `_archived/` and `_log/`.
4. **Dry-run the router.** `npm run toast:ingest:dry` (`package.json:66`) → expect: `timeseries CSVs: 3`, `SalesSummary zips: 0`, `LaborBreakDown zips: 0`, `--dry-run: skipping ingest` (`toast-weekly-ingest.mjs:144-155`). If a file lands under `unknown (skipped)`: rename it to the shapes in step 2 and re-run.
5. **Run the ingest against the live DB.** From repo root:
   ```bash
   export LARIAT_DATA_DIR="$HOME/Library/Application Support/Lariat/data"
   npm run toast:ingest
   ```
   → expect: `→ timeseries (3 CSV): node --experimental-strip-types …ingest-toast-timeseries.mjs --dir … --location default`, then `✓ ingested 3 file(s) → archived to data/imports/toast-weekly/_archived/<YYYY-MM-DDTHH-MM-SS-mmmZ>` and exit 0 (`toast-weekly-ingest.mjs:245`). If not: `✗ one or more ingest steps failed; leaving drop folder untouched.` and exit 1 (`:231-234`) — the files stay put; read the step output above it (header mismatch is the usual cause, `toast_csv.mjs:117`) and go to **If something goes wrong**. Or hand this step to an agent: say "dropped: <filenames> — run the toast weekly ingest" and it runs steps 4-6 and reports back (`SKILL.md:97-99`).
6. **Verify the DB moved.** Re-run the step-1 query → expect: `MAX(shift_date)` = last exported day, `MAX(imported_at)` = now, `COUNT(*)` ≥ 4407. `ls data/imports/toast-weekly/` → empty (unknown files, if any, remain — `:237-238`). `cat data/imports/toast-weekly/_archived/<stamp>/manifest.json` → `"all_ok": true` and `processed_files` lists your three CSVs (`:214-228`).
7. **Report it.** Paste into the chat of the session that asked (or the active one from `node scripts/agent-session.mjs list`): the archive path, the manifest's `all_ok` / `processed_files`, and the step-6 query line. Agents act only on your direct messages (`CLAUDE.md:301-302`).
8. **Optional — install the launchd job (defer until the agent pre-work below has merged).** The template hardcodes `HOME_DIR/Dev/Lariat` (`template:43,47,58,60`), and `~/Dev` is the unmounted SSD (`test -d ~/Dev` → exit 1, `CLAUDE.md:28-31`); it also sets only `PATH` in `EnvironmentVariables` (`:67-71`), so the job would write a stray `<repo>/data/lariat.db`. When the fixed template is in: use its own install command (`template:13-19`) with `HOME_DIR/Dev/Lariat` replaced by this checkout (`$PWD` from repo root), then `launchctl print gui/$(id -u)/com.lariat.toast-weekly | grep -E 'state|last exit'` (`:22`) → expect a `state` line. Install the **ingest** template, not the plist in `scripts/toast_api/README.md:82-111` — both claim label `com.lariat.toast-weekly` (`template:36`), and that one runs the unconfigured API pull. Remove with `template:28-29`.

## If something goes wrong
- Exit 1, folder untouched → nothing was archived and the DB transaction rolled back per step (`toast-weekly-ingest.mjs:29-31`; `ingest-toast-timeseries.mjs:123-130`). Fix the file (header/name) and re-run — full refresh per location, so re-runs are safe (`:26-27`).
- A stray `data/lariat.db` appeared in the repo → step-5 `export` was skipped; delete nothing yourself — tell the agent, which removes the stray file in its PR; re-run step 5 with the var exported.
- History shrank (`COUNT(*)` < 4407) → you exported a short window; restore from `backups/2026-09-02T11-11-34-266Z` only if you cannot re-export the full range (`go-live-venue-data.md:14-15`); otherwise re-export per step 2 and re-run.
- Zips: the orchestrator never passes `--db` (`toast-weekly-ingest.mjs:184-208`), and both Python scripts default to `<repo>/data/lariat.db` (`ingest_toast_sales_summary.py:54`, `ingest_toast_labor.py:47`) — sales summary exits 2 `ERROR: missing db` (`:304-306`), labor would create and write a stray DB (`:286`). Urgent labor only: run the script's own CLI by hand, `python3 scripts/ingest_toast_labor.py --zip data/imports/toast-weekly/LaborBreakDown_<s>_<e>.zip --db "$HOME/Library/Application Support/Lariat/data/lariat.db"` (`ingest_toast_labor.py:31-33`), then move the zip into `_archived/` yourself. Never hand-run the sales summary script on a weekly zip: `PERIOD_LABEL` is hardcoded to `2020-04-06_2026-04-12` (`ingest_toast_sales_summary.py:55`) and the DELETE keys on it (`:263-266`).
