## Pass / fail
A PR passes when: it is rebased on the latest `main` (`CLAUDE.md:169`; today all four base on `fdc708f2`), the body states the gate exit (`VERIFY_EXIT=0` — `.claude/skills/ship/SKILL.md:6-8`, `CLAUDE.md:170,199-208`), every `gh pr checks` line is `pass` or `skipping`, `mergeStateStatus` is `CLEAN`, and the diff does what the body says — no silent HACCP/PIN/audit weakening, no protected-surface change without its targeted suite (`CLAUDE.md` §5; `docs/PROTECTED_CONTRACTS.md` §15). Policy content (scope statements, hooks, per-edit cost) is your decision, not the gate's — say yes or no explicitly.
"Handled" for this recurring task: `gh pr list --state open` shows only PRs that carry a request-changes review plus a dated handoff line saying what the agent must do; `main` CI green after the last merge; merged branches' worktrees removed.

## If something goes wrong
- `main` CI red after a merge: `gh run view <run-id> --log-failed`; revert on a `fix/` branch with `git revert <squash-sha>` → PR → merge. Never push `main` (`CLAUDE.md:147`), never `reset --hard` (`CLAUDE.md:161-162`). The nightly 05:00 UTC run is the one that catches UTC-vs-Denver bugs (`.github/workflows/ci.yml:25-37`) — a PR green at midday can go red at 23:00 Denver; #676 exists because of that, so check the next nightly too.
- Merge refused / `DIRTY` / `CONFLICTING`: hand back (step 6). Do not resolve conflicts on `main` or in the agent's worktree.
- Step 8 refuses with files beyond the five: stop — another session's work. Leave it, say so in chat.
- `scripts/worktree.sh remove` refuses (uncommitted work): `git -C ../Lariat-worktrees/<wt> status --short`, do not `--force` (`scripts/worktree.sh:199-201`); hand the leftover to the agent that owns it.
- Merged the wrong thing: revert as above; the venue Mac is unaffected until it pulls `main`.
- Tell: append to `.agent-sessions/handoff.md` (`AGENTS.md:85`) and say it in chat.
