## Steps
1. **Have an agent pre-do the script/config mismatches (one PR, no secrets).** The README procedure (`desktop/README.md:45-53`) is contradicted by the packaging script in three places; a build with only the README steps done either fails or silently keeps skipping notarization:
   - a. `scripts/package-desktop.mjs:86` demands the literal `identity: null` in `electron-builder.yml` → with a real identity `npm run desktop:dist` exits `electron-builder.yml is missing required packaging rule: identity: null` (`:89-91`). Ask for the needle to be dropped or changed to `identity:`.
   - b. `scripts/package-desktop.mjs:174` runs electron-builder with `HOME=dist/.package-home`. `desktop/notarize.cjs:6` reads the env file from `os.homedir()`, which follows `$HOME` (verified: `HOME=/x node -e 'console.log(require("os").homedir())'` → `/x`), so `~/.lariat-build.env` is never read, and `security` loses the login keychain (`HOME=/x security default-keychain` → `A default keychain could not be found`, measured). Step 6 works around both with exported vars (`:172` passes `process.env` through) and `CSC_KEYCHAIN` (`node_modules/app-builder-lib/out/macPackager.js:51`, `codeSign/macCodeSign.js:63-66`); the durable fix is the script passing your real home/keychain to electron-builder.
   - c. electron-builder 26.8.1 notarizes by itself whenever `APPLE_ID`/`APPLE_APP_SPECIFIC_PASSWORD`/`APPLE_TEAM_ID` are in the env (`macPackager.js:342,501-527`), so with `afterSign: desktop/notarize.cjs` enabled the app is submitted twice. Ask for `notarize: false` under `mac:` (keeps the documented hook) — or drop the hook and keep the built-in; one, not both.
   → expect: that PR merged before you continue. If not: do a, and c yourself in the same branch as Close out; b is covered by Step 6.
2. **Set the identity.** Edit `electron-builder.yml:61` to `identity: "Developer ID Application: <Name> (<TEAMID>)"` — paste the exact string from `security find-identity -v -p codesigning` (`desktop/README.md:45-46`) → expect: `grep -n '^  identity:' electron-builder.yml` shows your string. If not: a typo here surfaces later as `Identity name is specified, but no valid identity with this name in the keychain` (`macCodeSign.js:59`).
3. **Enable the hook.** Uncomment `electron-builder.yml:66` → `  afterSign: desktop/notarize.cjs` (`desktop/README.md:47`) → expect: `grep -n '^  afterSign:' electron-builder.yml` prints one line. If not: the hook only fires after a real signature (`node_modules/app-builder-lib/out/platformPackager.js:333-339`), so it is inert until Step 2 holds.
4. **Create `~/.lariat-build.env`.** Exactly three lines, no quotes, no spaces around `=` (`desktop/README.md:48-53`, `electron-builder.yml:65`):
   ```
   APPLE_ID=you@example.com
   APPLE_APP_SPECIFIC_PASSWORD=xxxx-xxxx-xxxx-xxxx
   APPLE_TEAM_ID=ABCDE12345
   ```
   then `chmod 600 ~/.lariat-build.env` → expect: `grep -cE '^APPLE_(ID|APP_SPECIFIC_PASSWORD|TEAM_ID)=[^[:space:]]+$' ~/.lariat-build.env` → `3`, and `git check-ignore -v .lariat-build.env` → `.gitignore:200:.lariat-build.env` (proves a stray copy in the repo would stay untracked; `docs/desktop-packaging.md:137`). Never paste any of the three values into chat, a commit or a PR. If not: fix whitespace; the file lives in `$HOME`, not the repo.
5. **Dry-run the packaging contract.** `npm run desktop:dist:dry` → expect `Lariat desktop packaging plan`, three `$ …` lines and `Dry run complete. No build artifacts were written.` (`scripts/package-desktop.mjs:121-138`). If `missing required packaging rule: identity: null`: Step 1a is not merged.
6. **Build with the secrets exported (the HOME workaround from Step 1b).** In one shell, from the repo root:
   ```bash
   set -a; . ~/.lariat-build.env; set +a
   export CSC_KEYCHAIN="$HOME/Library/Keychains/login.keychain-db"
   set -o pipefail; npm run desktop:dist 2>&1 | tee ~/lariat-desktop-dist-$(date +%F).log
   ```
   (Apple Silicon only: `node scripts/package-desktop.mjs --arch=arm64 2>&1 | tee …` — `docs/desktop-packaging.md:71-75`.) → expect: a `signing … identityName=Developer ID Application: …` line, no `skipped macOS code signing` (`macPackager.js:220`), no `[notarize] … skipping` (`desktop/notarize.cjs:11`), `notarization successful` or the hook returning quietly, and the final `Desktop package complete. Artifacts are under dist/.` (`scripts/package-desktop.mjs:162`). The ad-hoc `afterPack` still runs first (`electron-builder.yml:54`, `desktop/after-pack-ad-hoc.cjs:15`) and is overwritten by the Developer ID signature — hook order is afterPack → sign → afterSign (`platformPackager.js:247-256,333-334`). If not: see the matching line under "If something goes wrong".
7. **Prove the app is signed, notarized and stapled** (gates from `docs/superpowers/plans/2026-08-05-h8-notarization.md:29-31`; stapling is automatic in `@electron/notarize` — `node_modules/@electron/notarize/lib/index.js:47`):
   ```bash
   grep -n 'notariz\|skipping\|skipped\|identityName' ~/lariat-desktop-dist-$(date +%F).log
   codesign --verify --deep --strict --verbose=2 dist/mac-arm64/Lariat.app
   spctl --assess --type execute -vv dist/mac-arm64/Lariat.app
   xcrun stapler validate dist/mac-arm64/Lariat.app

   ```
   → expect: `spctl` prints `accepted` with `source=Notarized Developer ID`; `stapler` prints `The validate action worked!`; `Lariat-0.1.0-arm64.dmg` (name pattern `electron-builder.yml:4`, version `package.json:3`). Repeat for `dist/mac/Lariat.app` if you built x64 (`scripts/package-desktop.mjs:221`). If not: `source=Unnotarized Developer ID` = signed but the notary step did not run or was rejected — check the grep line and "If something goes wrong".
8. **Clean-Mac launch (manual).** On another Mac or a fresh user, mount the `.dmg`, drag `Lariat` to Applications, double-click → expect: no "unidentified developer" / right-click-Open dance — the ad-hoc bypass in `desktop/README.md:92-95` is no longer needed (`h8-notarization.md:26,31`). ## If something goes wrong
- **`missing required packaging rule: identity: null`** (`scripts/package-desktop.mjs:86-91`): Step 1a not merged. Do not paste `identity: null` back into a comment to fool the check; fix the script.
- **Log still says `[notarize] … skipping`** (`desktop/notarize.cjs:10-12`): the three vars were not in the shell that ran the build — `HOME` is redirected at `scripts/package-desktop.mjs:174`, so the file alone is never read. Re-run Step 6's `set -a` line in the same shell, then build again.
- **`Identity name is specified, but no valid identity with this name in the keychain`** (`macCodeSign.js:59`) or **`skipping "afterSign" hook as no signing occurred`** (`platformPackager.js:338`): either the string in Step 2 does not match the cert, or the keychain is invisible under the redirected `HOME`. Compare `security find-identity -v -p codesigning "$HOME/Library/Keychains/login.keychain-db"` with `electron-builder.yml:61`, and make sure `CSC_KEYCHAIN` was exported (Step 6).
- **Notary rejected the upload** (`notarytool` reports `Invalid`): Apple's `xcrun notarytool log <submission-id>` with the same Apple ID / Team ID / app-specific password lists the reasons (this is Apple's tool, not a repo script). Usual causes: an entitlement in `desktop/entitlements.mac.plist` Apple will not accept, or a nested binary the `--deep` pass missed. Fix, rebuild, re-run Step 7.
- **Two notarization submissions in one build:** electron-builder's built-in notarize ran alongside the hook (`macPackager.js:342,501-527`) — Step 1c. Harmless once; fix before the next build.
- **Host binding broken after the build** (`ERR_DLOPEN_FAILED … 137 vs 147`): `CLAUDE.md:93-99`. Restore it yourself under Node 24 (`npm rebuild better-sqlite3` — owner only; agents never run it) and warn any live agent session.
- **Rollback:** revert `electron-builder.yml` to `identity: null` with `afterSign` commented (its `git diff` is the whole change) → the build is ad-hoc again and `desktop/notarize.cjs` no-ops with its warning (`desktop/README.md:55-56`). Delete `~/.lariat-build.env`.
- **Password or Team ID exposed** (chat, log paste, PR): revoke that app-specific password at appleid.apple.com immediately, generate a new one, rewrite the file (Step 4). Never commit the file — `git check-ignore -v .lariat-build.env` must keep answering `.gitignore:200`.
