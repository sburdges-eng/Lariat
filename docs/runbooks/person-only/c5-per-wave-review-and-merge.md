## If something goes wrong
- Rollback trigger: reconcile `FAIL` (exit 1) inside the 2-day window, or an operator-blocking write failure on a deleted route (`spec:79-84`).
- Revert first: `git revert -m 1 <merge-sha>` on a `fix/` branch → PR → merge (revertible commits, `spec:79-80`). Venue Mac: redeploy the prior web build (the `c5-pre-wave-1` tag or the pre-wave `main`) and restart the launcher (`docs/OPERATIONS.md:76`); native falls back to read-only by design (`LariatNative/Sources/LariatDB/LariatDatabase.swift:11` `readonly = true`; `LariatWriteDatabase.swift:15-16` never migrates).
- Data drift: restore from the pre-wave backup — `scripts/phase-c-backup.sh verify backups/<ts>`, then with web and native stopped copy `backups/<ts>/lariat.db` over `data/lariat.db` and untar `audit.tar.gz`. The script has only `backup` and `verify` modes (`scripts/phase-c-backup.sh:12-14`) — the restore itself is manual.
- The spec's "one command each, tested" fall-back switch (`spec:83-84`) does not exist in the repo. Have an agent build it before wave 1, or accept manual rollback in writing in the wave-1 log.
- Never lift the HACCP block or "fix" a reconcile FAIL by editing records (`.claude/skills/person-only/SKILL.md:83`; `LARIAT_NATIVE_FINAL_AGENT_GUIDE.md:93`).
- Tell: append the blocker to `.agent-sessions/handoff.md` and `ORCHESTRATOR_STATUS.md` (`AGENTS.md:85`).
