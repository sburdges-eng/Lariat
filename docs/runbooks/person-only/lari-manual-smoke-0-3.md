## If something goes wrong
- **AI is down card / 502 / `ollamaReachable:false`:** Ollama is not listening on `LARIAT_OLLAMA_URL` (`lib/ollama.ts:5`). `pgrep -fl "ollama serve"`; if absent, start it yourself in a spare terminal with the serving env: `OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 OLLAMA_KEEP_ALIVE=30m ollama serve` (`training/gcp/README.md:54-58`), then re-run the ping check. Every other surface keeps working meanwhile (`docs/OPERATIONS.md:78`).
- **Health says `model "lari-the-kitchen-assistant" not loaded`:** rebuild it — `ollama create lari-the-kitchen-assistant -f training/Modelfile` (`training/SETUP.md:10`); the GGUF it needs is present at `training/models/lari-ka-v2.gguf` (2.5 GB, 2026-08-30). Then `ollama list` should show it (`SETUP.md:63`).
- **Manager turn comes back `is manager-only…`:** no valid cookie in that tab — it expired (8 h, `route.ts:173`), you signed out, or the manager row is inactive (`lib/pin.ts:50-55`). Redo step 5.
- **"Manager PIN needed" card at login:** `LARIAT_PIN` is not in the running server's env (`middleware.js:96-107` sends `setup=1`). It was set and verified this morning (`README.md:13`), so a later restart lost `.env.local` — re-do `go-live-pin-login.md` / `env-local-pin-secret.md` steps 3-5 before continuing.
- **Garbled, cut-off, or invented answer:** most likely prompt truncation at `num_ctx 4096` (`lib/ollama.ts:137` vs `training/gcp/README.md:60-61`). Set `LARIAT_ASSISTANT_NUM_CTX=8192`, restart `npm run start` outside service, re-run from step 1. Record the failed attempt in the evidence either way — do not delete it.
- **Rollback:** nothing to roll back. Both queries are read-only SELECTs (`lib/dbQueryTool.ts:60,288`); the only writes are the append-only audit rows, which must never be edited or removed (`lib/auditEvents.ts:3-6`).
- **Mid-service:** do not restart the server or Ollama while the go-live session is serving — run the smoke before or after service. Who to tell: nobody, owner-only; record the outcome in this runbook's Status line.
