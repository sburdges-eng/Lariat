## Steps
1. **Find out exactly what is pending.** `bash scripts/bootstrap.sh; echo "exit=$?"` → expect either `bootstrap OK: gh, rg, jq, .venv python 3.13, node_modules present, gh authenticated` + `exit=0` (`scripts/bootstrap.sh:88-91`) or `INTERACTIVE STEPS REQUIRED (run these yourself):` followed by one line per step (`:84-87`). The script is idempotent and non-interactive (`:2-5`), and only touches Homebrew when something is missing (`:6,21-28`). If `exit=0` but the hand-back named `codex`, `hermes` or OAuth, go to step 4, 5 or 6.
2. **`gh auth login` (if listed).** `gh auth login --web` → answer GitHub.com; keep HTTPS as the git protocol (`~/.config/gh/hosts.yml` already says `git_protocol: https`); at "Authenticate Git with your GitHub credentials?" answer **No** unless you want gh to replace git's current `osxkeychain` helper (`git config credential.helper` = `osxkeychain` on 2026-09-02); paste the one-time code in the browser. Then `gh auth status` → expect `✓ Logged in to github.com account sburdges-eng (keyring)` and scopes including `repo` and `workflow` (what `gh pr create` and `gh run list` need). If not: see the keyring note under "If something goes wrong".
3. **Homebrew / nvm / venv lines (if listed).** Each needs your password or a shell restart, which is why the script refuses them (`scripts/bootstrap.sh:24,53,62`). Manual actions: install Homebrew with its own interactive installer; then re-run step 1 and let the script `brew install` gh/rg/jq/python@3.13 itself (`:21-32,44-45`). For `nvm install 24`: install nvm from the link the script prints (`:62`), open a new shell, `nvm install 24`. Never `brew install node` (`:57-58`). Re-run step 1 after each until `exit=0`. On this laptop 2026-09-02 none of this applies (node v24.20.0, `.venv/bin/python` 3.13.15, `node_modules` present).
4. **`codex` (if the hand-back names `codex resume` / `codex login`).** In the Codex terminal: `codex login status` → expect `Logged in using ChatGPT` (non-interactive; `codex login --help` lists `status`). 5. **`hermes model` (if named).** In your terminal: `hermes model` — the interactive provider/model picker (`~/.hermes/hermes-agent/README.md:71`; `~/.local/bin/hermes` is a 4-line wrapper that execs `~/.hermes/hermes-agent/venv/bin/hermes`). 6. **Browser OAuth (if named).** Complete the OAuth flow in the browser yourself; there is no repo command (`CLAUDE.md:130-131` only names the category). Done when the tool that asked shows the connector as connected.

## If something goes wrong
- **`X Timeout trying to log in to github.com account sburdges-eng (keyring)`, exit 1:** observed 2026-09-02 as transient — the next run passed. Re-run once. If it persists, unlock the login keychain (Keychain Access) and retry; only then `gh auth login --web` again.
- **`gh auth status` is green but `git push` asks for a password:** git's HTTPS credential comes from `osxkeychain`, not gh (`git config credential.helper`; remote `https://github.com/sburdges-eng/Lariat.git`). Fix yourself: re-run `gh auth login --web` and answer **Yes** to "Authenticate Git with your GitHub credentials?" (or `gh auth setup-git`). Never hand a token to an agent.
- **`FAILED installs: <formula>`** (`scripts/bootstrap.sh:80-83`): a non-interactive `brew install` failed — run that `brew install <formula>` yourself, read its error, re-run step 1.
- **`WARNING: shell node is vNN; repo pins 24`** (`:63-64`): informational; the gate forces node@24 via npx. Do not `brew install node` (`:57-58`).
- **`scripts/bootstrap.sh: No such file`:** you are on a branch cut before #674. Run the checks by hand: `gh auth status; command -v gh rg jq; node -v; .venv/bin/python -c 'import sys;print(sys.version)'; ls -d node_modules`.
- **Rollback:** nothing in the repo changes — state lives in your keychain, `~/.codex/auth.json` and `~/.hermes/auth.json`. `gh auth logout` returns gh to the pre-step state.
- Who to tell: the agent that stopped (chat or `.agent-sessions/handoff.md`). Nobody else.
