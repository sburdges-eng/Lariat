A database created through the native migrator no longer matches a web-created one.

### Aug 23 monthly makeup is unconditional — `lib/augustChecklists2026.ts:89`

```ts
export const AUGUST_MONTHLY_DATES = ['2026-08-16', '2026-08-23'] as const;
```

The comment says "target Sun Aug 16, makeup Sun Aug 23", but the check is a plain
`.includes(isoDate)` with no completion test anywhere in the module. Both dates emit all

### `summarize()` honours its date parameter for ~30 counts but not one

`lib/commandCenter.ts` reads `ops_run` from `serviceDate()` while everything else uses the
caller's `today`. That was deliberate — it keeps the Command tile consistent with the
board it links to — but for dated callers (`/api/command/summary?date=…`, `/morning?date=…`)
the ops counts come from today beside a link carrying the historical date. It closes when
wave 5 moves the remaining callers and the parameter itself becomes a service date.

## 4. Decisions that are yours, not mine

**How much does the HACCP gate need to prove?** The gate on `fix/day-plan-haccp-gate` is a
*precondition*, not a completeness claim: it blocks closing a food-safety step when
**nothing at all** was written to that board for the shift.

It is deliberately not "the work is done", because there is no completeness signal to
gate on. `TempPoints` carry temperature thresholds, not a per-shift schedule, and points
like `receiving_cold` only apply when a delivery happened; sanitizer, TPHC, cooling and
date marks are the same shape. Asserting completeness would mean inventing regulated
policy. If you want a real completeness gate, the rule has to be defined per board first
— a food-safety decision.

**Does the day plan belong in the service-date waves?** It is a wave 1 surface by the
spec's own shape (an API route holding both defaults plus a page holding a third), absent
from the listed seven only because it postdates the 2026-08-06 spec. The spec and #619's
title both still say seven.

## 5. Environment traps

These cost real time this session. Cursor on your Mac will differ from the CI container
in the first two.

- **Node.** The repo pins 24 (`.nvmrc`); `better-sqlite3` is compiled for it. Any
  DB-touching test needs `npx -y node@24 --experimental-strip-types --test <file>`.
  Never `npm rebuild better-sqlite3` — it breaks other sessions.
- **The server runs UTC.** `serviceDate()` and `localNowMinutes()` both handle this
  correctly now, but anything new that reads `getHours()` or `toISOString().slice(0,10)`
  will be hours out in production and *look right on your Mac*. This is how the lateness
  bug survived.
- **`next build` catches what nothing else does.** A `'use client'` file importing a
  `lib/*` module that reaches for `node:crypto` or `node:fs` passes tsc, eslint and
  `node --test`, and fails only at build. `lib/serviceDate.ts` is Intl-only by design for
  exactly this reason, since `DayPlanBoard.jsx` imports through to it.
- **No Swift toolchain in the cloud container.** Native changes can only be validated by
  CI's `swift build + test`. On your Mac they run locally.

## 9. Food cost

The question that opened this session — what is food cost — is now answerable, but not
from anything in this handoff. #627 landed a verified Sysco backfill (127 orders, May 2025
→ Jul 2026, 90.9% food share on the committed lines). The labor side is solid and
independent:

```
Net sales      $1,093,748.36     TTM, period stamped 2026-04-01
Labor          $267,996.61       24.5% of net
```

That 24.5% **excludes all salaried staff** — 4,081.1 hours across the two GM rows sit at
$0. And 3,990.3 further hours sit on non-person placeholders (`Bar Night`, `Bar Day`,
`Security Team`, `Non usable employee`). If those placeholder hours were worked and paid,
labor is understated by roughly $48k and 24.5% becomes ~28.9%.

`scripts/audit_labor_zero_cost.py` settles it, given the raw export:

```bash
python3 scripts/audit_labor_zero_cost.py --export-dir dev/exports/2026-04-01 \
    --payroll-total <gross payroll for the period>
```

`--payroll-total` is the decisive input — the gap against this export's labor cost is the
answer with no inference. `--punches` is the fallback if payroll is not to hand.
